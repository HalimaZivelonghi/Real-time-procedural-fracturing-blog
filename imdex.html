Mesh Splitting

The foundation of the whole system is a mesh splitter that divides any mesh along an arbitrary plane, producing two independent halves with clean, capped interiors. The algorithm follows the approach described in Geometric Tools — Clip Mesh , which I adapted into a C++ CMesh class.

mesh split — before / after

Initialization

Vertices, edges, and faces are loaded into dedicated structs that track adjacency, index, and which side of the cut plane they belong to. A ClipMode enum lets the caller request only the positive or negative half, enabling early exits and avoiding geometry work that would be thrown away.

CMesh.cpp — Clip entry point
int CMesh::Clip(glm::vec4 plane, ClipMode mode)
{
    if (ProcessVertices(plane) == 1)  // all vertices on positive side
        return 1;
    else if (ProcessVertices(plane) == -1)  // all vertices on negative side
        return -1;

    ProcessEdges(mode);
    ProcessFaces(plane, mode);

    return 0;
}

Process Vertices

Every vertex is classified as positive or negative by computing its signed distance to the cutting plane. No geometry is moved at this stage — the classification just drives everything that follows.

Process Edges

Edges whose endpoints share a side stay intact. Edges that cross the plane are split: the intersection point is found via linear interpolation using the signed distances at each endpoint, a new vertex is inserted there, and the edge is divided into a positive half and a negative half sharing that new vertex. This is what produces the clean cut line across the surface.

Process Faces & Closing

Faces that land entirely on one side are trivially assigned. Faces cut by the plane have an open boundary — a closing edge is added to seal each of them, and those closing edges collectively form the flat interior cap sitting exactly on the cutting plane.

CMesh.cpp — Open polyline detection
bool CMesh::GetOpenPolyline(CFace face, size_t& start, size_t& final)
{
    // reset occurrence counts on all edge vertices
    for (size_t j : face.edge)
    {
        m_cVertices[m_cEdges[j].vertices.first].occurs = 0;
        m_cVertices[m_cEdges[j].vertices.second].occurs = 0;
    }

    for (size_t j : face.edge)
    {
        m_cVertices[m_cEdges[j].vertices.first].occurs++;
        m_cVertices[m_cEdges[j].vertices.second].occurs++;
    }

    start = std::numeric_limits<size_t>::max();
    final = std::numeric_limits<size_t>::max();

    // vertices with occurs == 1 are the open endpoints
    for (size_t j : face.edge)
    {
        size_t i0 = m_cEdges[j].vertices.first;
        size_t i1 = m_cEdges[j].vertices.second;

        if (m_cVertices[i0].occurs == 1)  final = i0;
        if (m_cVertices[i1].occurs == 1)  start = i1;
    }

    return start != std::numeric_limits<size_t>::max();
}

Clean-up, Triangulation & Normals

Each output face is triangulated in a fan from its first vertex. Faces with fewer than three valid vertices after filtering are skipped. Normals start as per-face cross products accumulated into shared vertices, though at the very end they are recalculated as flat normals — the fractured look reads more clearly with hard facets than with smooth shading.

Because new intersection vertices are created independently per edge, near-duplicate points can appear along the cut. A remapping pass merges any pairs within an epsilon threshold, preventing invisible cracks in the closing cap.

Voronoi Generation

With a working splitter, the next question was how to produce a realistic fracture pattern. Voronoi fracturing scatters random seed points inside the mesh's bounding volume and divides space so every point belongs to the cell of its nearest seed. Cutting along all cell boundaries produces the final fragments. Voronoi cells are always convex, which makes them a natural fit for a physics engine and gives patterns that read as naturally irregular.

Voro++

Rather than implementing Voronoi from scratch I used Voro++, a C++ library for 3D Voronoi computation. The container is sized to the mesh's bounding box, seeds are scattered randomly inside it, and for each computed cell the library yields face normals and one vertex per face. Those are transformed into world space by adding the seed point position, then a plane is built from each face. The result is a list of clipping planes per cell that fully describes its geometry.

Fracturer.cpp — Building cell planes from Voro++ output
for (int k = 0; k < cell.number_of_faces(); k++)
{
    int face_size    = face_vertices[face_start];
    int vertex_index = face_vertices[face_start + 1] * 3;

    glm::vec3 localVertex(
        vertices[vertex_index],
        vertices[vertex_index + 1],
        vertices[vertex_index + 2]);

    glm::vec3 worldVertex = localVertex + seedPoint;

    glm::vec3 normal(
        -face_normals[k * 3],
        -face_normals[k * 3 + 1],
        -face_normals[k * 3 + 2]);

    float d = glm::dot(normal, worldVertex);
    glm::vec4 plane(normal.x, normal.y, normal.z, d);
    cell_planes.push_back(plane);

    face_start += face_size + 1;
}

Fracturing

With Voronoi planes ready, the Fracturer applies them to produce debris pieces. For each cell it takes a fresh copy of the original mesh and progressively clips it against every plane in that cell's list, keeping only the positive side each time. What remains is the geometry belonging to that cell.

Fracturer.cpp — Per-cell clipping loop
const auto& cell = cellPlanes[k];
std::vector<glm::vec3> currentPositions = m_mesh->GetPositions();
std::vector<uint16_t> currentIndices  = m_mesh->GetIndices();

for (size_t j = 0; j < cell.size(); j++)
{
    const auto& plane = cell[j];
    CMesh cmesh;
    cmesh.FillDataCMesh(currentPositions, currentIndices);
    cmesh.Clip(plane, ClipMode::Positive);
    cmesh.GetPositiveData(currentPositions, currentIndices);
}

Once all cells are processed, each resulting piece is handed to Jolt as a convex hull collision shape and added to the scene as an independent physics body.

Optimization was a core part of the project. Every clip operation touches every vertex and edge in the mesh, and Voronoi fracturing does dozens of cuts per cell — the naive approach had no chance of holding at runtime.

Convex Hull Simplification

Raw fracture output can carry a lot of geometry, especially on cut faces. Rather than feeding the rendered mesh directly to the physics engine, each piece is run through Jolt's ConvexHullShapeSettings after fracturing, building a simplified convex hull from the vertices. This also serves as the point where normals are recalculated as flat ones, improving shading without incurring extra storage cost.

Multithreading

Each Voronoi cell is fully independent — it works on its own copy of the mesh data and writes to its own output slot. No shared state, no locking required. The only constraint is that anything touching OpenGL must stay on the main thread, so mesh upload and physics body creation are deferred until all worker threads finish.
